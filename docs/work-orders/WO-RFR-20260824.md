## 3. Full loop-engineer cycle — mandatory per remediation slice

Each finding or tightly coupled finding group must complete the whole loop before it is marked done:

`Grill Me / Grill Me with docs -> Brainstorm -> Plan -> Implement -> Review -> Debug -> Test/E2E -> Report -> Memory -> Open PR -> CI/CD -> Fetch merge state`

### Stage requirements

1. **Grill Me / Grill Me with docs**
   - Challenge the requested fix, assumptions, trust boundaries, failure modes, and done criteria before coding.
   - For `grill-with-docs`, verify the local skill against its upstream GitHub source when network access is available. Record upstream URL/ref/date used.
   - If upstream freshness cannot be checked, say `UPSTREAM_UNVERIFIED` and use the pinned local copy; never claim it is up to date.
2. **Brainstorm**
   - Generate at least two viable approaches when design risk is non-trivial.
   - If the current CLI supports subagents, fan out independent design/security/test perspectives. Subagent output is advisory; the primary agent owns the decision.
3. **Plan mode / deep reasoning**
   - Define root cause, invariants, files, tests-first sequence, rollback, and exact acceptance evidence.
   - Keep work micro-stepped and independently resumable.
4. **Implement**
   - Follow Iron Law test-first for production changes.
   - One coherent finding group per branch/PR unless coupling is proven in the plan.
5. **Review**
   - Use an independent reviewer or stronger reasoning mode where available.
   - Review code, security, tests, integration, and regression surface; approval is pinned to exact SHA.
6. **Debug**
   - Any failure requires root-cause isolation before patching. Do not weaken tests to get green.
7. **Test / E2E**
   - Run targeted unit tests plus realistic end-to-end/adversarial usage that crosses the real integration path.
   - Distinguish transport/tool failure from product/test failure.
8. **Report**
   - Record commands, decisive outputs, changed files, residual risks, and reviewer verdict in this work order or the canonical review artifact.
9. **Memory**
   - Persist reusable defect-prevention lessons in the repository's approved durable memory/knowledge mechanism. Do not store secrets/private paths. The lesson must describe how to prevent recurrence, not merely restate the bug.
10. **Open PR**
    - Push the remediation branch and open a draft PR to `main` before independent final review when CI evidence depends on PR events.
11. **CI/CD**
    - Required CI must pass at the reviewed PR HEAD. Never treat an unrelated workflow run as evidence.
12. **Fetch merge state**
    - Reviewer never silently assumes merge. After the human/authorized merge gate, fetch `origin`, verify the PR merge/resulting `main` SHA, then update this work order/checkpoint. If not merged, state `AWAITING_MERGE`.
